# Выгрузка UI в фоне

## Поведение

- При скрытии окна в трей или сворачивании сразу останавливаются UI-опросы трафика, групп, памяти и соединений, а также анимационные tickers.
- Через **3 секунды** невидимости `SuspendableUi` удаляет дерево `HomePage` вместе с посещёнными страницами `NavigationPageView`. Вызываются обычные `dispose`, освобождаются контроллеры экранов. После кадра выгрузки очищается переиспользуемый image cache и кэш измерений высот.
- При открытии окно восстанавливает выбранную страницу из состояния приложения. Быстрое скрытие/открытие до истечения задержки не пересоздаёт экраны. Повторные сигналы скрытия не продлевают таймер.
- Потеря фокуса сама по себе не означает скрытие и не выгружает видимое окно.
- На macOS источником видимости является `NSPopoverDelegate`: открытие, закрытие через статус-бар, Escape и клик снаружи. Используется существующий канал `status_bar_icon`; запоздавший первоначальный ответ не перекрывает более свежее событие.
- На Windows/Linux используются show/hide и minimize/restore/focus, а открытие из трея также восстанавливает минимизированное окно. На Android используется жизненный цикл Flutter; независимый VPN service engine не затрагивается.

## Что остаётся работать

Flutter engine, `Application`, `Navigator`, `AppController`, Riverpod-состояние и платформенные менеджеры остаются живыми. Они управляют треем, IPC, ядром и настройками. Выгрузка этих владельцев в текущей архитектуре завершила бы ядро, а не только интерфейс.

Продолжают работать VPN/прокси, активные соединения, core health checks, настроенное логирование, автоматическое обновление подписок/провайдеров и сервисные уведомления. Таймер выгрузки одноразовый; периодический принудительный GC не добавляется.

Операции конфигурации, переключения профиля и импорта больше не зависят от наличия `homeScaffoldKey.currentState`: `runWithOptionalUi` показывает прогресс при наличии UI, а без него выполняет операцию через существующую обработку ошибок. Статус запуска для трея публикуется непосредственно при запуске, а не ожидает первого UI-опроса.

## Защита ввода и незавершённых действий

Если поверх главной страницы открыт редактор, диалог или sheet, дерево владельца сохраняется. Редактирование раскладки dashboard защищено существующим `backBlockProvider`. `loadingRun` удерживает UI на время импорта/сохранения и других незавершённых операций; удержание освобождается в `finally`.

Даже при отложенной выгрузке анимации и UI-опросы в невидимом окне остаются выключенными. Для фактического демонтажа без обычного vsync используется один `scheduleWarmUpFrame` на переход состояния, а не постоянный фоновый рендеринг.

## Проверка

Проверено локально 8 сентября 2026:

- `flutter test --no-pub --reporter expanded`: **157 тестов прошли**, включая 22 новых проверки жизненного цикла, выгрузки кэшированных страниц, сохранения ввода, native-канала, фоновых операций и кадров при выключенном vsync.
- `flutter analyze --no-pub`: новых диагностик нет; до и после изменений одинаковые 576 существующих замечаний (572 info, 4 warning, 0 error). Команда всё ещё возвращает ненулевой код из-за существующих замечаний.
- `git diff --check`: успешно.
- `xcrun swiftc -frontend -parse macos/Runner/AppDelegate.swift`: синтаксис Swift проверен. Это не полноценная сборка и не проверка нативного поведения.

Полная macOS-сборка и проверки на устройствах не выполнены: активный developer directory указывает на Command Line Tools, а `xcodebuild` требует полноценный Xcode. Изменения `AppDelegate.swift` требуют пересборки приложения, одного Dart hot reload недостаточно.

### Ручная проверка перед выпуском

1. Включить прокси, открыть несколько вкладок, свернуть/скрыть приложение больше чем на 3 секунды. Проверить `Background UI unloaded` в диагностическом логе и отсутствие разрыва соединений.
2. Вернуть окно: выбранная вкладка должна восстановиться, текущие показатели — обновиться. Повторить быстрое скрытие/возврат много раз.
3. В Windows/Linux с выгруженным UI проверить запуск/остановку и изменение режима из меню трея, автоматическое обновление профиля и открытие ссылки импорта.
4. В macOS проверить закрытие popover кнопкой, Escape и кликом вне него, затем повторное открытие.
5. Скрыть окно во время редактирования профиля, открытого диалога, изменения раскладки dashboard и долгого импорта. Проверить сохранность ввода и завершение операции.
6. На Android проверить сворачивание и изменение состояния VPN через плитку/уведомление, затем возврат в приложение.

Численные выигрыши CPU/RAM/батареи не измерялись. Для сравнения нужны одинаковый release/profile build, профиль, трафик и набор вкладок до/после изменения. Освобождение дерева/объектов не гарантирует немедленное снижение RSS: движки Flutter/Dart/Go и системные аллокаторы могут сохранять зарезервированную память.
